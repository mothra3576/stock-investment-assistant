# 第3-A：本人用の銘柄マスターと形式v2

## 実ファイルの確認状況

JPX公式の実ファイルは提供されておらず、ヘッダー・シート構造・掲載日程は未確認です。JPXへの自動アクセスはしていません。公式ファイルを使った照合済み専用パーサーではなく、利用者が実際のシートと列を確認して指定する汎用取込です。列名や商品区分の意味を推測して自動固定しません。テストの表はすべて人工データであり、JPXの書式・実データを再現したという主張ではありません。

実ファイル確認後に検証すべき事項は、拡張子、シート名、ヘッダー行、コードのセル型、業種なしの表記、基準日の場所・型、市場・商品区分の実際の値、普通株式とETF/REIT等の対応です。実データを公開テストやリポジトリに追加しないでください。形式検証だけでは上場事実や取得権限を保証できません。

## iPhoneでの手順

1. 本人がSafariで[JPXの東証上場銘柄一覧ページ](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)を開き、利用条件と掲載基準日を確認して一覧ファイルをダウンロードします。アプリはこの操作を代行しません。
2. 「ファイル」アプリなど本人用の保存先に置きます。対応は `.xlsx` とUTF-8 CSVです。入手ファイルが旧 `.xls` の場合は、Excel/Numbers等で開いて `.xlsx` かUTF-8 CSVへ変換してください。コード列は文字列で維持し、先頭ゼロを失わないようにします。拡張子を変更するだけでは変換になりません。Shift_JIS CSV・暗号化Excel・四半期の財務表はこの取込対象ではありません。
3. アプリの下部ナビ「銘柄一覧」→「銘柄一覧ファイル」で選択します。Excel/CSVは8MB以下、最大8シート・64列・12,000データ行です。ヘッダーは読み取った先頭50行から選択します。Excelの展開容量は32MB以下、読込はWeb Workerで行い、30秒で中断します。
4. 読み取ったシート名・行プレビューを確認し、コード・企業名・市場区分・業種の列を個別に選択します。同じ列を必須4項目へ重複指定することはできません。業種に `-` などの表記があれば元の文字列として残します。空欄を自動的に「その他」で補完しません。
5. 商品区分の元列を選び、元の値ごとに普通株式／ETF／REIT／その他／未分類を対応付けます。市場区分の列も選べます。名称や証券コードからは推定しません。未設定は「未分類」であり普通株式ではありません。異なる商品が一つの値に混在し対応できない場合は未分類のままにするか、本人が元ファイルに分類列を付けてから取り込みます。
6. 基準日の列を選択するか、元ファイル・掲載ページで確認した基準日を手入力します。列の日付は全行一致を要求します。YYYY-MM-DD、YYYYMMDD、Excel日付セルに対応します。取込日時を基準日の代わりには使いません。列と手動指定が食い違えばエラーです。
7. 「インポート前プレビューを作成」で件数、エラー、重複統合数、未分類数、先頭の銘柄を確認します。エラーは先頭100件まで表示し、1件でもあれば保存できません。
8. 「この内容でマスターを保存」を押して初めてIndexedDBに保存します。現在の全マスターを置換します。以前より古い基準日のファイルも明示確認後に置換するため、基準日を確認してください。
9. 検索・市場・業種・商品区分で絞り込みます。50件ずつのページ表示で数千件を扱います。銘柄名をタップすると既存の分析画面へ進み、本人の財務v1データがなければ「データなし」と表示します。

## 更新・重複・削除

コードは英数字4〜5文字を保持し、大文字と半角へ正規化します。数値セルの整数は文字列化し、文字列の先頭ゼロは保持します。失われた先頭ゼロや5桁コードの末尾を推測して補正しません。将来EDINET/J-Quantsのコード体系を対応させる際は、別アダプターで仕様を確認して変換します。

同一ファイル内で、正規化したコードと内容が完全に同一の行は1件へ統合します。同じコードで企業名・市場・業種・商品区分が異なればエラーです。基準日と全銘柄内容が保存済みデータと同一なら再追加せず、前の取込日時を維持します。行順やファイル名の違いだけでは増殖しません。更新版は1つのreadwriteトランザクションで全体を置換し、エラー・中断時は元の保存内容を保持します。

「保存済みマスターを削除」→「削除を確定」でマスターだけを消せます。ウォッチ・財務・学習は別保存で残ります。マスターから消えたコードのウォッチを勝手に削除しません。

## バックアップとv2 JSON

「マスターをv2 JSONでバックアップ」は端末にだけファイルを作成します。Safariでダウンロードまたは共有メニューから「ファイルに保存」を選びます。「銘柄一覧ファイル」でそのJSONを選び、復元プレビューを確認して復元できます。最大32MBです。復元も形式・件数・重複を検証してから全置換し、最終更新日時は復元時刻になります。

バックアップはマスターのみです。ウォッチ、既存財務、学習履歴、元のExcelファイルは含みません。現時点でそれら全体のバックアップ・復元機能はありません。重要な財務データは元CSV/JSONを保管し、ブラウザデータを消す前にこの制約を確認してください。将来のOneDrive同期・全体バックアップでは各Repositoryを通して統合し、削除・競合・バージョン移行を設計します。

構造例の文字列はすべて説明用の人工データです。

```json
{
  "version": 2,
  "kind": "security-master",
  "source": "user-file",
  "asOfDate": "2026-09-30",
  "dateOrigin": "manual",
  "fileName": "personal-master.xlsx",
  "sheetName": "本人が選択したシート",
  "importedAt": "2026-10-24T00:00:00Z",
  "records": [
    {
      "id": "JP:130A",
      "code": "130A",
      "name": "架空検証企業",
      "marketSegment": "本人が確認した市場区分",
      "sector": "本人が確認した業種",
      "securityType": "unknown"
    }
  ]
}
```

`dateOrigin` は `column` または `manual`、`securityType` は `ordinary` / `etf` / `reit` / `other` / `unknown`。空一覧・不正なID・重複コード・不正な日付や区分は復元不可です。v2には株価・財務数値を入れません。既存の配列形式v1は変更せず、「銘柄分析」のCSV/JSON取込から使用します。

## 保存と財務の結合

`MasterRepository` が専用DB `stock-investment-master` v1の単一スナップショットを管理します。データ形式v2とIndexedDBのバージョン番号は別です。既存の `stock-investment-analysis` と `stock-investment-assistant` は変更しません。

マスター登録中の銘柄分析はマスターを母集団とし、本人が財務v1で取り込んだデータだけを `JP:コード` の完全一致で結合します。マスターの企業名・業種を優先し、財務の会計期間・実績予想・出典・価格基準日は維持します。架空サンプルを自動的に結合しません。結合されないコードや米国株のv1データは消去せず保存し、マスター削除後は従来の一覧で表示できます。

財務未取得の企業は `periods: []`、株価・時価総額・株価日付などは `null`。会計期間を架空作成したり、銘柄マスターの基準日を株価基準日に流用したりしません。0配当など実際に入力された0は欠損と区別します。財務条件を付ければ欠損値は既存ルールに従って検索から除外されます。
